分层／权限边界

向下的箭头，是唯一合法的动作

这是整套契约里唯一不可协商的一条：raw/ 由人类拥有，LLM 绝不修改、绝不重命名、绝不删除。上三页的每一条约束都由它推出。

机制

每条结论都能钉回一个文件

链条上挂四个字段：raw_sha256 管完整性、source_count 管证据独立性、confidence 管定级、Contradictions 节管矛盾照录。去程是摄入，返程才是校验。

机制／四条派生规则

链条上丢一个字段，就断一处

完整性 raw_sha256 对不上就报 SOURCE MODIFIED，须重新摄入并更新所有受影响页面。
独立性 source_count 只数去重后的 raw 文件，不数来源页、不数章节——一本教材的十节在证据意义上不独立，逐节累加等于让一份材料给自己凑够三个来源。
定级 1 个来源 low；3+ medium；5+ 且无重大矛盾 → 候选 high，须人工确认才可写入。个人写作永不计数。
不覆盖 来源之间、以及同一材料内部的矛盾一律并列照录。两套口径分属不同文件且材料未说明效力关系时，不得择一为准。

检索

三个阶段，只跑一个

① 扩写这一步仍然发生，只是执行者换成了 LLM 自己写的 vec:／lex: 变体；③ 精排整段取消（--no-rerank）。装了三个，只跑一个。

检索／性能

同一个问题，两条路差 185 倍

被规避的那条不是「不好用」，而是这台机器上跑不动——光重排 20 个块就占掉 1165 秒。而自写扩写 ＋ --no-rerank 这条，检索器自己的源码就把它称为「给有能力的 LLM 推荐的端点」。

三个模型是谁

三者均 GGUF v3、合计约 1.7 GB，身份证取自各自的 GGUF 头元数据。「不加载」不等于「可以删」——不带 --no-rerank 时它们仍会被加载，那正是 19 分 47 秒的由来。

检索／一条硬约束

换 embed 模型 ＝ 现有向量全部作废

fingerprint = hash(
　模型 URI ＋ 查询侧提示词格式 ＋ 文档侧提示词格式
　＋ 分块 token 数 ＋ 重叠 token 数 )

所以换 embed 模型、或者只是改一下分块参数，既有 5,259 块都会因指纹对不上而被判为过时。

代价是整库重嵌，约 3 小时 25 分（纯 CPU，约 0.32 块/秒）。 这不是改一行配置的事——改之前先想清楚。

这也是唯一一处「配置写错不会有报错、只会悄悄让检索变差」的地方，所以单列一页。

收尾

三句话

一 分层的判据是归属权，不是文件类型——raw/ 你拥有、我绝不写，wiki/ 我全权、你随时可查。
二 每一条结论都得能溯源到一份原始文件，而且能反向核对——来源页是证据，概念页只是加工品。
三 检索只跑一个模型。另两个装着、安静地待着，但随时可能被一次不带 --no-rerank 的命令唤醒。

库外还有三处会在仓库改名或迁移时坏掉——按这张单子核：~/.config/qmd/index.yml 的 path（不改则检索全废）、~/.config/obsidian/obsidian.json 的 vault 路径（不改则 Obsidian 打不开）、.venv/bin/activate*（不改则 source 后环境变量指错）。

顺便点一下左边那三条色带——全篇只用这三种颜色代表三层，之后看到颜色就知道在讲哪一层，图例就在下面。

要讲的对比是这句：语料 4,952 个文件，知识层只有 526 页。

为什么这么薄？不是没时间，是摄入口径要求每条要点都人工确认。所以消化速度由这道关口决定，不由文件量决定——这是设计出来的慢，不是没做完。

可以补一个细节：索引里的 506 恰好等于四个内容目录之和，模板页与报告页被刻意排除在检索之外，因为它们不是知识。

【如果被问】raw/制度 有 4,895 个，为什么只精摄了一部分？——是分层摄入：第一层 111 篇优先，其余留在 raw 层作可检索语料。

判据是归属权，不是文件类型——这是全篇的骨架，后面每条约束都由它推出。

指着三个色带讲：raw 你拥有、我只读；wiki 我全权、你随时可查；工具层谁都拥有不了。

中间那条横带是权限边界。整套契约里唯一不可协商的东西就是它——下一页专门讲。

向下的实线是唯一合法的动作；向上的虚线被红叉划掉。

为什么这么严？因为 raw/ 是唯一事实来源。只要 LLM 能改来源，整条证据链就失去意义——链条的起点必须在我控制之外。

所以「写入 / 改名 / 删除」三件事一律不做，没有例外、没有「这次帮我改一下」。这条要说得硬一点。

去程是摄入，返程才是校验——底下那条朱砂色的线下一页单独讲。

四个字段各管一件事，念一遍就够：raw_sha256 管完整性、source_count 管证据独立性、confidence 管定级、Contradictions 节管矛盾照录。

【如果被问】为什么结论不能只引概念页？——概念页是加工品，来源页才是原始材料的直接映射。所以 QUERY 的结论必须溯源到来源页。

这是全套机制里最值得讲的一件事，可以放慢。

关键在三个检查问的问题不一样：检查 2 问「页面在不在」，检查 3 问「登没登记」，检查 10 问「指对没有」。

21 个概念页把《税法（二）》的税种引到了《税法（一）》的题库来源页上。因为那个 slug 真实存在，前两项检查根本问不出来——错误静默活了 11 轮。

教训一句话：断链检查不等于正确性检查。目标存在，不代表指对了。

重点讲「独立性」那条，因为它最反直觉：为什么一本教材只算一个来源？

因为同一本书的各章节在证据意义上并不独立。逐节累加，等于让一份材料给自己凑够三个来源，confidence 就虚高了。

这条和「个人写作永不计数」是同一条原则——不能自己给自己背书。

这一页快速过，重点在三个「绝不自动」：MERGE 绝不自动合并、LINT 绝不自动改页面、REFLECT 找不到反驳来源就必须标注回音室风险。

INGEST 那个「核心要点须逐一人工确认」是整条链上唯一的外部输入，也是它慢的原因。

容易误解的一点：① 扩写这一步仍然发生，只是执行者从 Qwen3-0.6B 换成了 LLM 自己写的 vec: / lex: 变体；③ 精排则是整段取消。

反直觉的地方：另两个模型不能删——不带 --no-rerank 时它们会被加载，那就是下一页 19 分 47 秒的由来。

差 185 倍。但重点不是「默认的不好用」，而是这台机器跑不动：无 GPU，重排要对每个候选块做 4096 token 全量前向，光重排 20 个块就占掉 1165 秒。

补一句安心的话：自写扩写这条不是权宜之计——检索器自己的源码就称它为「给有能力的 LLM 推荐的端点」，理由是外部 LLM 能写出比它自带小模型更好的查询变体。

文件名只写了量化、没写是谁，所以把身份证列出来。

上游对照值得记：embed 和 rerank 就是 qmd 原配、与官方默认同源同文件；generate 是唯一被替换过的——原配的 1.7B 专用扩写模型魔搭没有镜像，所以启用了源码里被注释掉的旧默认。

这一页是写给未来的自己看的。

fingerprint 把模型名、两套提示词格式、分块与重叠参数一起哈希进去。所以换 embed 模型、或者只是改一下分块参数，5,259 块全部作废，代价 3 小时 25 分。

这是全库唯一一处「配置写错不报错、只会悄悄让检索变差」的地方，所以值得单列一页。

lint 十项里最耐人寻味的是那张裁定表：四类「看起来像问题、其实不是」。

前三类的共同前提是命名本身无误——相似是因为领域结构本来就相似。为迁就一个启发式检查去合并它们，代价是毁掉页面与法规结构之间的对应关系。

只有第四类（词序置换／单复数差异）要动手改，因为那种相似是命名疏漏，检索时必然拿错页。

三句话回顾即可，不要展开。

最后一定要念库外那三处：仓库改名或迁移时，这三处不在仓库里的引用会「静默」坏掉——检索全废、Obsidian 打不开、环境变量指错。

可以顺口加一句：这不是假设，这次会话里刚实际发生过一次。
